# Nowen Forge V0.9 — Release Evidence

V0.9 把发布证据链补到 GitHub `run_attempt` 和 Docker Registry digest 层。

## Run Attempt Evidence

同一个 GitHub Workflow Run 被 rerun 时，Run ID 不变，但 `run_attempt` 会递增。Forge 不覆盖旧证据，而是追加保存：

```text
Workflow Run #100
├─ attempt #1
│  ├─ failure
│  └─ 精确 Job 快照
└─ attempt #2
   ├─ success
   └─ 精确 Job 快照
```

Job 使用 GitHub 的指定 attempt jobs API 获取。Workflow Artifact 仍是 Run 级证据，因为 GitHub 没有按 attempt 精确列 Artifact 的接口，Forge 不伪造归属。

## Docker Manifest Evidence

对支持 Docker 的项目，Forge 使用 Docker Registry API 获取：

```text
cropflre/nowen:v1.2.3
├─ manifest digest: sha256:...
├─ linux/amd64: sha256:...
└─ linux/arm64: sha256:...
```

记录采用 append-only。若同一个版本 Tag 以后被覆盖推送到不同 manifest digest，历史观测不会被覆盖，制品中心会直接标记 digest 变化风险。

## 自动补抓

- 创建或再次固化 Manifest 时自动抓取当前 completed `run_attempt` 与 Docker evidence。
- Release Recovery 后 10 分钟内，服务端 Evidence Watcher 会持续补抓最新 attempt / Docker digest。
- 浏览器关闭不会影响恢复后的证据补抓。
- 制品中心可以手动点击「同步全部证据」。

## API

```text
GET  /api/evidence/manifests
GET  /api/evidence/manifests/:manifestId
POST /api/evidence/manifests/:manifestId/sync
GET  /api/evidence/capabilities
```

## 数据表

```text
manifest_run_attempts
manifest_docker_evidence
```

两张表都只追加历史证据，不修改原 `release_manifests` 核心快照。
